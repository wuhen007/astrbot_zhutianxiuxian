## 一、平台能力与硬约束（判定依据）

| 能力 | 实现 | 硬约束（判定的根） |
|---|---|---|
| **MD 消息** | `use_markdown(True)` → msg_type=2 | 群聊原生 MD 需机器人权限；被拒自动降级纯文本 |
| **内联键盘** | `Button`+`ActionRow` → msg_type=4 | **最多 5 行 × 每行 5 按钮 = 25 个选项**；label 短（截断）；回调 data ≤1024B |
| **回调点击** | `@register_button_action` + `event.get_button_interaction()` | 回调数据必须 ≤1024B → **只能放短参数**，不能承载自由输入；registry 内存态**重启失效** |
| **降级** | 键盘/MD 被拒自动发 `fallback_text` | 其他平台（NapCat 等）自动回落纯文本指令，零回归 |

**判定铁律**（每个玩法按此打分）：
- 按钮适合作 ✅：后续是**离散 ≤25 个选项**且可从回包上下文推出参数（选择/确认/翻页/一键）
- 按钮不适合作 ❌：需要**自由输入**（金额/物品名/@对象/坐标）或**无后续分支**（单发结果）
- MD 适合作 ✅：**多行结构化数据**（面板/列表/表格）；❌：一句话结果、与出图互斥的重呈现

### ❌ C. 明确不能（原因）

| # | 玩法组 | 为什么不能 |
|---|---|---|
| C1 | 单发结果类：签到、抽奖、突破成功回包、渡劫结算、进阶结算 | **无后续分支**——按钮的意义是承载"下一步"，结果已终态，加按钮是噪音 |
| C2 | 自由输入核心类：转账/借款还款、兑换码、购买/出售、物品使用/装备、命格改命（花灵石确认可按钮但金额固定） | 核心参数是**金额/码文本/物品名**，1024B 回调可放但**输入法打字比按钮更直接**——按钮只能覆盖确认步骤 |
| C3 | 出图重呈现类：位面方图、劫境构筑图、立绘剧情、命格图鉴出图、锻造图纸 | MD 与图片**同消息互斥**（QQ 富媒体与 MD payload 二选一）；图的呈现力 > MD，保留出图。可在图后单独跟一条按钮消息（W32 实测项） |
| C4 | 超级管理员/元系统权柄（19 条） | 管理指令需精确参数与日志审计，保持纯文本；MD 化反而降低可复制性 |
| C5 | 跨玩家实时对局主流程：切磋/比武/秘境攻击/仙宠对战 | 攻击对象需 @；对局节奏 <5s，按钮点击延迟反而破坏节奏（应战确认按钮可保留） |
| C6 | 无尽劫境战斗模/构筑（选择道法后） | 组合空间 >25 且依赖构筑状态，按钮枚举爆炸 |
| C7 | 文本彩蛋类：打桩/怡红院/柠檬堂等 | 单发娱乐文案，无分支 |
| C8 | 信息列表类 15 条（#我的练气/#练气境界 等） | 纯只读展示——MD 可排版但**无按钮场景**（无下一步）；MD 收益低，排 W32 尾 |

## 三、技术设计（W30 基建，不变）

```
core/mdui.py
├─ btn(action_id, label, data, style) / row(*btns, fallback, timeout)
├─ send_md(event, title, body, *rows)   # MD 正文+键盘，自动 fallback
└─ own(data, uid)                       # 回调 data 注入发起者，防冒用

main.py
└─ @register_button_action(None) 通用分发器：
      data={uid, act, a1, a2} → 校验点击者 → 路由到既有 core 调用（幂等不变）
```

- 回调 data 白名单四元组（1024B 内），业务参数只从回包上下文派生
- `action_timeout` 对齐业务窗口（探索/抉择 60s、撤离读条+120s、命签 10 分钟）
- 超时点击 → AstrBot expiry notice → 提示重发指令（fallback 文本同义）

## 五、结论

- **完整可做 18 组**（A）：全离散分支/一键动作，按钮收益最大
- **部分可做 16 组**（B）：MD 面板全量可做，按钮只覆盖无参步骤——自由输入是 QQ 按钮模型的天然边界
- **不能做 8 类**（C）：单发终态、自由输入核心、出图互斥、管理审计、实时对局、组合爆炸、纯彩蛋、只读无交互——每类原因如上表
